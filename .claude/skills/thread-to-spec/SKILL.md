# Thread to Spec

Når du lager en spec fra en tråd er målet å destillere en rotete diskusjon til noe strukturert som noen utenfor tråden kan forstå og ta stilling til.

## Workflow

### 1. Les gjennom hele tråden
- Les alt materialet før du begynner å strukturere — konklusjoner tidlig i en tråd blir ofte justert senere
- Identifiser hvem som sa hva, og om det er uenighet eller uavklarte punkter som ikke bør fremstilles som avgjort

### 2. Trekk ut kjerneinnholdet
- **Hva ønsker vi å løse?** Hvilket problem er det tråden faktisk handler om?
- **Hvordan foreslår vi å løse det?** Hva ble diskutert som løsning, og hva var eventuelle alternativer som ble vurdert og forkastet?
- Noter åpne spørsmål eller punkter tråden ikke kom til enighet om — ikke lukk dem på egen hånd

### 3. Strukturer specen
- Bruk et format som er lett å skumme: overskrifter, korte avsnitt, punktlister
- Inkluder minst: problem, foreslått løsning, eventuelle alternativer vurdert, åpne spørsmål
- Kutt alt fra tråden som var relevant for diskusjonen der og da, men ikke for noen som leser specen senere

### 4. Lever resultatet
- Presenter specen for brukeren for gjennomlesning
- Hvis brukeren ønsker den publisert et sted (f.eks. Notion), bruk `write-doc-to-notion`-skillen for å finne riktig sted og publisere

## Tone

Skriv for noen som ikke var med i tråden. Vær presis om hva som faktisk ble besluttet versus hva som fortsatt er åpent.
